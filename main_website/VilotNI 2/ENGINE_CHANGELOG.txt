[2026-09-26] FOCUSED QUERY / EVIDENCE / RANKING FAST PATH
- Added QueryPlanner.js. It converts parsed language state into a compact, non-factual search contract: requested role, subject/predicate/object anchors, expected POS shape, focus seeds, complexity, and candidate budget. It includes the same executable production-research extension pattern used by the existing V2 modules.
- Added EvidenceSearch.js. It builds a small high-relevance candidate pool from Words.json associations, learned RSL transitions/context/correlations, WordState support, and WordMatrix support before broad lexical search begins. It includes its own executable production-research extension.
- Added CandidateRanker.js. It ranks already-generated candidates by confidence, grammar, completion, answer contract, language-state support, focused evidence coverage, directness, and structural penalties. It never increases or replaces Decoder confidence. It includes its own executable production-research extension.
- FastLane now attempts the focused route first. Straightforward prompts normally generate a compact 4-8 candidate batch instead of entering broad repeated search immediately.
- The strict >80% emission invariant remains unchanged. Focused ranking cannot make a sub-80% candidate eligible.
- If the focused batch misses the confidence floor, the existing widening/recovery search continues automatically with the focused evidence pool, then expands that evidence pool when recovery mode begins.
- Decoder accepts a prebuilt static candidate pool and tracks focused-evidence support as a trajectory feature, allowing the query planner to reduce irrelevant lexical competition without hardcoding answer text.
- Context-dependent short prompts can still use the fast route when they have grammatical-role and learned recurrent evidence; self-contained prompts do not require prior conversation context.
- Added cache-busting runtime version v=2-focused-fastpath-1 and exposed route/planner/evidence/ranker diagnostics through Worker/FastLane status.
- TrainingInfo.json remains dormant on the pure VilotNI 2 live-response path.
